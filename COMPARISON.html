01 / MOBILE PLAY

手机接着看：直链直发，中转兜底

原版根本没这个功能。初版实现犯过一个错：把「播放地址」直接塞二维码——但那经常是网页/解析页， 或者 127.0.0.1:9978/proxy 这种只有电视自己能访问的本机代理。现在的逻辑是 双通道：真直链免 WiFi 直发，防盗链源回退电视中转。

MOBILE PLAY · 决策管线
┌──────────────────────┐      ┌───────────────────────────────┐
│  点击「手机播放」  │ ───▶ │ 缓存命中? goPlayUrl 落点缓存   │
└──────────────────────┘      │ App.getResolvedPlay(key)      │
                              └──────────────┬────────────────┘
                                             ▼
                        ┌────────  isDirectPlayUrl()?  ────────┐
                        │ http(s) 且无 127.0.0.1/localhost//proxy?│
                        ▼                                      ▼
              ┌───────────────────┐              ┌───────────────────────┐
              │ 默认中转模式      │              │ 直链模式(可切换)      │
              │ /m?u=base64(addr) │              │ QR = 播放地址本身     │
              │ 电视带UA/Referer  │              │ 免WiFi·防盗链源会403  │
              └───────────────────┘              └───────────────────────┘
BEFORE原版 / 初版
// 地址从显示层 TextView 抠出来，
// 经常是解析页或本机回环代理
String raw = tvPlayUrl.getText().toString()
    .replace("播放地址：", "");
// 无脑 base64 塞进中转页
String qr = base + "m?u=" + encode(raw);
AFTERTvBox-NY
// ① 起播时缓存真实解析后地址（PlayFragment.goPlayUrl）
App.getInstance().putResolvedPlay(
    sourceKey + "|" + vodInfo.playFlag + "|" + vodInfo.playIndex, url);

// ② 直链判定：回环/代理地址手机指不到
private static boolean isDirectPlayUrl(String u) {
    return u.startsWith("http")
        && !u.contains("127.0.0.1")
        && !u.contains("localhost")
        && !u.contains("/proxy?");
}

// ③ 双模式：默认中转(防盗链源可播)，OK 键切直链(免WiFi)
new MobilePlayDialog(ctx, relayUrl, playAddr).show();

关键认知：直链不是万能的。源站校验 UA/Referer 时手机浏览器裸拉就是 403， 所以默认走电视中转（同一 WiFi，电视代为带正确的头拉流），弹窗里按 OK 一键切直链。

02 / REMOTE ENGINE

网页遥控器：自己造焦点引擎

原版遥控网页形同虚设。深挖后发现问题在 Android 的焦点管线： dispatchKeyEvent 手动派发不走 ViewRootImpl 的焦点查找 fallback， 触摸模式下更是没有任何 View 持有焦点——按什么都没用。所以方向键不能"派发"， 要自己做焦点导航。

BEFORE直觉写法（全部失效）
// ✗ dispatchKeyEvent 不做焦点查找
//   (卡在 ViewPostImeInputStage)
activity.dispatchKeyEvent(new KeyEvent(KEYCODE_DPAD_DOWN));

// ✗ Instrumentation API 28+ 要 INJECT_EVENTS 权限
new Instrumentation().sendKeyDownUpSync(code);

// ✗ focusSearch 传 keycode 直接崩：
//   Unknown direction: 22
view.focusSearch(keyCode);
AFTERRemoteServer.handleWithFocus
// 方向键：keycode → View.FOCUS_* 方向常量
int dir = keyCode == 20 ? View.FOCUS_DOWN
        : keyCode == 19 ? View.FOCUS_UP
        : keyCode == 21 ? View.FOCUS_LEFT
        : View.FOCUS_RIGHT;
View next = decor.findFocus().focusSearch(dir);
if (next != null) next.requestFocus(dir);
else decor.requestFocusFromTouch();  // 无焦点兜底

// OK=performClick · BACK=onBackPressed · 其余键 dispatchKeyEvent 兜底
// 每次按键返回回执: "focus:20:TvRecyclerView"

前端同样配合：摇杆带 16px 死区 + 三档连发（340/190/115ms）+ 换向震动， 每个按键的回执直接显示在遥控页状态行（上 ✓ sent:19:HomeActivity），问题看得见。

03 / WALLPAPER

壁纸引擎：多源兜底链 + 真解码校验

"换张壁纸接口全失败"的根因：单源 + 只重试一次，而且有些图床返回 200 + HTML—— HTTP 层看着成功，落盘全是文本。解法是按类别排序的候选源链 + BitmapFactory 真解码一次。

BEFORE原版思路
// 单源，失败只重试一次同一源
private static final String ENDPOINT =
    "https://uapis.cn/api/v1/random/image";

void retryOrGiveUp(String failedUrl) {
    String next = nextUrl();      // 还是同一个源
    if (!next.equals(failedUrl)) download(next);
    else toast("失败");           // 单源挂=永远失败
}
// 且不校验内容：200 + HTML 也当成功
AFTERWallpaperHelper.nextFallback
// 候选链：主源 → 类别匹配备源 → 通用兜底
nextFallback(category, tried) →
    uapis.cn?category=cat        // 主源
  → t.alcy.cc/ycy or /pc        // 樱花,按类别选
  → api.paugram.com/wallpaper    // 通用兜底

// 已失败的源按裸前缀记入 wpTried，逐个换源,
// 每个候选拼时间戳防 CDN 缓存; 全试过才放弃

// 不信任状态码，真解码一次：
BitmapFactory.decodeFile(tmp, opts.setJustDecodeBounds());
return opts.outWidth > 0 && opts.outHeight > 0;

下载先落 wp_tmp，校验通过才 rename 成 wp——图源抽风也不会把原来那张能用的壁纸冲掉。

  • 搜索页三栏对齐

    原版按钮等宽堆叠、三栏参差。现在：搜索主键琥珀实心、次键 ghost；节标题统一为「大家都在搜 HOT / 搜索结果 RESULTS / 搜索历史 HISTORY」，三栏顶部基线对齐；键盘按键 50→44 收敛降噪。

  • 遥控网页单屏重构

    208px 导航环 + 76px 琥珀 OK 钮 + 摇杆 + 大返回（onBackPressed 级别，不是模拟器小返回），1080×1920 零滚动。

  • NTP 毫秒级卡点

    同步阿里云 ntp.aliyun.com，定时任务精准到毫秒——卡点场景不再差半拍。

  • 省份并发 + 集中日志

    多省份请求并发提速，日志集中汇总回显；遥控按键带回执，出问题一眼定位。
